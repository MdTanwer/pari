## 1. Overview & Evaluation Philosophy

A primary reason agent architectures degrade over time is the absence of an automated, deterministic evaluation harness. Engineers tweak prompts, introduce new tools, or adjust system parameters, and then subjectively test the agent on a single toy task.

PARI builds **Evaluation and Structured Observability directly into the core CLI**:
* Engineers can execute a local 10-issue benchmark suite (`pari eval run`) for under **$5.00** in API costs.
* Every agent turn emits structured machine-readable JSON logs for telemetry and regression tracing.
* Testing is strictly deterministic, relying on compiler exit codes rather than subjective LLM judges.

## 2. The Local Micro-Eval Suite

```bash
pari eval run --suite ./evals/micro_suite.json
```

```
+-----------------------------------------------------------------------------------+
|                        MICRO-EVAL SUITE EXECUTION FLOW                            |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  1. CLONE & CHECKOUT: Clone test repo & checkout base_commit into temp workspace  |
|         |                                                                         |
|         v                                                                         |
|  2. SANDBOX BOOT: Launch isolated bwrap / Seatbelt container locked to workspace |
|         |                                                                         |
|         v                                                                         |
|  3. AGENT RUNTIME: Inject issue prompt (e.g. "Fix IndexError in auth")            |
|         |          Agent executes tools and applies edits (max 25 turns)          |
|         v                                                                         |
|  4. IMMUTABLE TEST GUARD:                                                         |
|         Execute: git checkout base_commit -- tests/                               |
|         (Guarantees agent cannot pass by tampering with test assertions)          |
|         |                                                                         |
|         v                                                                         |
|  5. VERIFICATION: Execute test command inside sandbox (e.g. pytest tests/)        |
|         Exit code 0 = PASS | Exit code non-zero = FAIL                            |
|         |                                                                         |
|         v                                                                         |
|  6. TELEMETRY: Record duration, turns, cost USD to evals/results_<timestamp>.json|
|                                                                                   |
+-----------------------------------------------------------------------------------+
```

### The Six Invariant Execution Steps

1. **Clean Workspace Isolation**: The eval harness clones the repository into an ephemeral directory and checks out the designated `base_commit`.
2. **Sandbox Initialization**: Layer 0 boots a fresh Bubblewrap/Seatbelt container locked strictly to the temporary workspace.
3. **Turn-Capped Run**: PARI executes with a maximum limit of 25 turns to resolve the reported issue.
4. **Immutable Test Guard**: Prior to executing the verification test suite, the harness forcibly runs:
   ```bash
   git checkout base_commit -- tests/
   ```
   **This prevents the agent from "passing" the benchmark by deleting or commenting out failing test assertions.**
5. **Deterministic Verification**: Runs the project test command (e.g. `pytest tests/test_issue.py`, `cargo test`, `npm test`). Exit code `0` is PASS; non-zero is FAIL.
6. **Telemetry Artifact Generation**: Generates a comprehensive JSON results file in `evals/results_<timestamp>.json` recording duration, pass status, cost in USD, and token count.

## 3. Cross-Model Verification (The Graptile Principle)

When optional qualitative assessment is requested (`pari eval judge`), PARI enforces the **Graptile Principle of Cross-Model Verification**:

$$\text{\bf Code generated by Model Family } A \text{\bf\ must be evaluated by Model Family } B.$$

* If PARI used **Anthropic Claude 3.7 Sonnet** to generate the solution, the evaluation judge is automatically routed to **OpenAI GPT-4o** or **DeepSeek R1**.
* If PARI used an **OpenAI** model, evaluation is routed to **Claude 3.5 Sonnet**.
* **Rationale**: LLM families exhibit strong self-evaluation confirmation bias, consistently rating code written with their own idioms higher than code written by competitors. Cross-model evaluation provides objective scrutiny.

## 4. Structured Observability via `structlog`

Every agent turn emits structured, machine-parsable JSON logs to `.pari/logs/session.jsonl`:

```json
{"timestamp": "2026-10-03T09:12:01.120Z", "event": "tool_call", "turn": 12, "tool": "bash", "cmd": "pytest tests/test_auth.py", "sandbox": "bwrap"}
{"timestamp": "2026-10-03T09:12:01.890Z", "event": "edit_applied", "turn": 12, "tier": "git_osr", "file": "src/auth/service.py", "lines_changed": 4}
{"timestamp": "2026-10-03T09:12:02.450Z", "event": "turn_complete", "turn": 12, "tokens_in": 14200, "tokens_cached": 12100, "tokens_out": 340, "cost_usd": 0.0094}
```

This telemetry enables automated monitoring of:
* Cache hit ratios across multi-turn sessions.
* Diff cascade tier distributions (tracking what % of edits resolved via Tier 1 vs. Tier 2 vs. Tier 3).
* Latency breakdowns per tool execution.

## 5. Chaos Testing Harness

To guarantee system resilience before production releases, PARI includes an automated Chaos Test Suite:
* **Fork-Bomb Attack**: Executes `:(){ :|:& };:` inside sandbox; verifies cgroups v2 kills processes without crashing host.
* **CPU / Memory Throttle**: Stresses memory to 3 GB; verifies cgroups cleanly triggers OOM killer without host freeze.
* **SIGKILL Mid-Turn**: Issues hard `kill -9` to the PARI process during an active file write; verifies `FileMutationQueue` left zero torn files and Layer 1 CRC32 scan safely recovers session state.
* **Concurrent Write Flooding**: Launches 20 parallel async file write tasks against the same canonical file; verifies 0 write tears and exact serialized execution.
